02

Um Redis só não segura o sistema

Com uma instância central, a queda da máquina derruba leitura e escrita. A vazão também fica presa ao hardware de um único host.

O gargalo

Ponto único de falha. Tudo passa pelo mesmo processo: consultas, gravações e a disponibilidade do serviço.

O que a prática faz

Um master recebe as escritas e replica em segundo plano. A réplica atende leituras e pode assumir o papel de master.

03

Quem escreve e quem lê

Topologia primário-secundário. A replicação é assíncrona: o master confirma a escrita e segue, sem esperar a réplica.

Master

REDIS01

192.168.50.10

  • Processa todo SET
  • Mantém o backlog de replicação
  • Envia o fluxo para a réplica
assíncrono

Replica

REDIS02

192.168.50.20

  • Modo somente leitura
  • Responde GET
  • Pode ser promovida no failover

04

Full sync, PSYNC e o CAP

Primeira conexão

Full sync

O master gera um snapshot RDB da memória e envia pelo socket. A réplica monta o estado base a partir desse arquivo.

Rede oscilou

PSYNC

A réplica reconecta informando o offset. O master reenvia só os bytes que ficaram no backlog, sem um RDB novo.

C

Consistência eventual. A escrita volta ao cliente antes de chegar na réplica.

A

Disponibilidade. O master não bloqueia novas requisições enquanto replica.

P

Partição. Uma queda breve de rede não exige sincronizar o banco inteiro de novo.

Essa escolha deixa uma janela de replication lag. Se o master cair antes de esvaziar o buffer, o que ainda não foi enviado pode se perder no failover.

06

O que foi configurado

IP estático no Netplan, bind do Redis no endereço da rede interna e a réplica apontando para o master.

Netplan · REDIS01

/etc/netplan/00-installer-config.yaml

network:
  version: 2
  ethernets:
    enp0s3:
      dhcp4: true
    enp0s8:
      addresses: [192.168.50.10/24]

Aplicar com sudo netplan apply. Na réplica, o endereço é 192.168.50.20/24.

Redis · master

/etc/redis/redis.conf

bind 127.0.0.1 -::1 192.168.50.10
protected-mode no

Depois: sudo systemctl restart redis-server. Na réplica, o bind usa 192.168.50.20.

Ativar a réplica

REDIS02

redis-cli replicaof 192.168.50.10 6379
redis-cli config rewrite

O config rewrite grava o replicaof no arquivo para sobreviver ao reinício.

07

Três testes no cluster

Cenário 1

Escrita, leitura e bloqueio

A chave gravada no master aparece na réplica. A tentativa de escrever na réplica é recusada.

redis-cli -h 192.168.50.10 set turma "Sistemas Distribuidos"
OK
redis-cli -h 192.168.50.20 get turma
"Sistemas Distribuidos"
redis-cli -h 192.168.50.20 set teste 123
(error) READONLY You can't write against a read only replica.

Cenário 2

Queda do master

O serviço do primário é parado. A réplica percebe o link cair e mantém os dados que já estavam em memória.

sudo systemctl stop redis-server
redis-cli info replication
master_link_status:down

Cenário 3

Failover manual

A réplica é desvinculada e passa a aceitar escrita. O cluster continua operando sem o master original.

redis-cli replicaof no one
redis-cli info replication
role:master
redis-cli set status "Recuperado com sucesso"
"Recuperado com sucesso"

08

A mesma prova, em Python

O script conecta nos dois IPs com a biblioteca python3-redis, espera a réplica e trata o erro de escrita.

No Ubuntu 26.04 o pip install global é bloqueado pelo PEP 668. O pacote usado foi sudo apt install -y python3-redis.

# teste_cluster.py
master = redis.Redis(host="192.168.50.10", port=6379,
                     decode_responses=True, socket_timeout=3)
replica = redis.Redis(host="192.168.50.20", port=6379,
                      decode_responses=True, socket_timeout=3)

master.set("disciplina", "Sistemas Distribuidos")
time.sleep(0.5)
valor = replica.get("disciplina")

try:
    replica.set("tentativa", "erro")
except redis.exceptions.ReadOnlyError:
    print("[Réplica] Escrita bloqueada")

09

O que quebrou no laboratório

  1. YAML do Netplan

    Problema. etwork: e a indentação de addresses impediram o IP de subir.

    Solução. Dois espaços por nível e a forma curta addresses: [192.168.50.10/24].

  2. Nome errado no systemd

    Problema. systemctl restart REDIS01 devolveu Unit REDIS01.service not found.

    Solução. O serviço do pacote é sudo systemctl restart redis-server.

  3. Hostname depois do clone

    Problema. A VM clonada continuou como REDIS01. O cloud-init desfazia a troca no reboot.

    Solução. hostnamectl set-hostname REDIS02 e preserve_hostname: true em /etc/cloud/cloud.cfg.

  4. VMs sem se enxergar

    Problema. ping com Destination Host Unreachable e master_link_status:down.

    Solução. Subir as duas máquinas e rodar netplan apply na enp0s8. A perda ficou em 0%.

  5. pip bloqueado

    Problema. pip install redis parou em externally-managed-environment.

    Solução. sudo apt install -y python3-redis.

10

O que a prática confirmou

Réplica acompanha o master

SET em 192.168.50.10, GET em 192.168.50.20, mesmo valor.

Réplica não aceita escrita

O modo read-only devolve READONLY e evita divergência local.

Failover devolve a escrita

replicaof no one muda o papel para master e o nó volta a gravar.
